# genschema

Genschema generates JSON Schema for [Kubernetes Configuration APIs](https://kubernetes.io/docs/reference/config-api/) and other Kubernetes-related configuration file types that cannot be obtained from the apiserver's `/openapi/v3` endpoint.

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                     kubeschema.nvim (Neovim plugin)              │
│          Dynamic schema matching based on apiVersion/kind        │
└───────────────────────────┬─────────────────────────────────────┘
                            │ reads schema files
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                    ~/.config/kubeschemas/                        │
│                   (schema file repository)                       │
├──────────────────────┬──────────────────────────────────────────┤
│  k8s builtins + CRDs │  configuration file schemas              │
│  (dumped by          │  (generated by genschema)                 │
│   kubeschema tool)   │                                          │
└──────────────────────┴──────────────────────────────────────────┘
                            ▲
                            │ generates
┌─────────────────────────────────────────────────────────────────┐
│                      genschema (this tool)                       │
│  Uses k8s openapi-gen to produce JSON Schema for config types   │
│  that are not available via apiserver OpenAPI:                  │
│  - kubeadm config, kubelet config, kube-proxy config            │
│  - kubeconfig, kubescheduler config                             │
│  - EnvoyGateway config, Gateway API types, Agones types         │
└─────────────────────────────────────────────────────────────────┘
```

**What genschema covers**: Kubernetes configuration file types (kubeadm, kubelet, etc.) and external API types (EnvoyGateway, Gateway API, Agones) that are defined in Go but not served by the apiserver's OpenAPI endpoint.

**What genschema does NOT cover**: Kubernetes built-in resources (Pod, Deployment, etc.) and CRDs — those are dumped from live clusters by the [kubeschema](https://github.com/imroc/kubeschema) tool.

## Quick Start

### Prerequisites

- Go (version matching the k8s branch, see `go.work`)
- protoc (auto-installed by `hack/update-codegen.sh`)

### Build and run

```bash
cd genschema

# 1. Generate openapi code (runs hack/update-codegen.sh)
make codegen

# 2. Generate JSON schemas (writes to ./schemas/ by default)
make run

# Override output directory via flag:
go run . -o ~/.config/kubeschemas

# Or via Makefile + env var:
OUTPUT_DIR=~/.config/kubeschemas make run
```

### One-step build

```bash
make all  # runs codegen + run
```

## Adding External APIs

External APIs (e.g. EnvoyGateway, Agones) need their Go type definitions copied into `staging/src/` so that `openapi-gen` can process them.

### Step 1: Pin the version

Add the repo and version to `versions.txt`:

```
myapi=v1.2.3
```

### Step 2: Add clone target

Add a `clone-myapi` target to the `Makefile`:

```makefile
clone-myapi:
	git clone https://github.com/org/myapi.git
	@cd myapi && git checkout $$(grep '^myapi=' versions.txt | cut -d= -f2)
```

Add it to the `clone` dependency list.

### Step 3: Add sync-code target

Add a sync target to copy type definitions into `staging/src/`:

```makefile
ma:
	mkdir -p ../staging/src/example.com/myapi/apis/v1
	cp myapi/api/v1/*_types.go ../staging/src/example.com/myapi/apis/v1/
```

Add it to the `sync-code` dependency list.

### Step 4: Add go.mod

Create `staging/src/example.com/myapi/go.mod`:

```
module example.com/myapi

go 1.26.0
```

### Step 5: Register in go.work

Add the module to `go.work`:

```
./staging/src/example.com/myapi
```

### Step 6: Add openapi-gen tag

Ensure `doc.go` in the API package has:

```go
// +k8s:openapi-gen=true
```

### Step 7: Register in main.go

Add an entry to the `apis` slice in `main.go`:

```go
{Prefix: "example.com/myapi/apis", Group: "myapi.example.com"},
```

### Step 8: Generate

```bash
make clone-myapi
make sync-code
make codegen
make run
```

## How It Works

1. **codegen**: `make codegen` runs `hack/update-codegen.sh openapi` with `GENERATED_FILE_PREFIX=genschema.` This invokes `openapi-gen` which scans all packages tagged with `// +k8s:openapi-gen=true` and generates a single `genschema.openapi.go` file containing all OpenAPI definitions.

2. **schema generation**: `make run` executes `main.go` which:
   - Iterates over all OpenAPI definitions from the generated code
   - Filters to only those matching entries in the `apis` list (prefix match, in order)
   - For each matching type, resolves its group/kind/version via `parseNameRef`
   - Writes a JSON Schema file to `<group>/<kind>_<version>.json`
   - For types with `apiVersion`/`kind` properties, adds `enum` constraints

3. **schema references**: Cross-type references use relative paths (`../<group>/<kind>_<version>.json`) so the schema directory is self-contained.

## Troubleshooting

### openapi-gen error: "not sure how to enforce default for Func"

A type contains a `func()` field. Add `// +k8s:openapi-gen=false` to the field or containing type in the source.

### openapi-gen error: "illegal character U+0001"

Corrupted doc.go file (from a bad sed/regex insertion). Re-apply the `// +k8s:openapi-gen=true` tag manually.

### API rule violations for pkg/apis/core

The `pkg/apis/core` modification triggers `streaming_list_type_json_tags` violations. These are expected and do not affect schema generation. The `make codegen` target will print the violation diff but still produce the output file.

### "method already declared" compile error

Leftover `genschema.model_name.go` files in staging. The Makefile's `codegen` target cleans these up automatically. If they persist, run:

```bash
find ../staging ../cmd ../pkg ../plugin -name 'genschema.model_name.go' -delete
```
